## 문제와 목적

원작 영걸전은 DOS 전용이라 현대 환경에서 플레이하기 어렵고, 데이터·그래픽 개조가 사실상 불가능하다. 본 프로젝트는 원작의 게임 시스템과 플레이 감각을 유지하면서 다음을 달성한다.

- **유지**: 원작 데이터(무장·병과·능력치·시나리오)와 플레이 방식(턴제 전투, 상성, 책략, 일기토, 사실/가상 분기). 인게임 맵은 논리 구조를 원작과 동일하게 재현한다.
- **교체 허용**: 타일맵·스프라이트·애니메이션 등 시각 요소는 취향에 따라 자유 교체(맵 논리 구조는 유지).
- **개선**: 조조전식 전투 중 턴 중간 세이브/로드, 게임 내 장수 정보 에디터.
- **핵심 요구**: 병과·병종을 수정/추가하면 엔진 코드 수정 없이 데이터와 UI가 함께 자동 반영되는 구조.

## 대상과 시나리오

- 대상: 프로젝트 소유자 1인. 개인 플레이·개조 전용이며 배포하지 않는다.
- 주요 시나리오:
  1. 원작 시나리오를 처음부터 엔딩까지 통 플레이(사실/가상 루트 분기 포함).
  2. 전투 중 임의 시점에 저장하고 나중에 이어서 플레이.
  3. 장수 에디터로 능력치·레벨·초상화를 수정하고 모든 캠페인에 반영.
  4. 데이터/그래픽 개조: 병종 추가, 밸런스 상수 조정, 스프라이트 교체.
  5. 릴리스 태그 푸시 한 번으로 윈도우·맥 설치본 생성.

## 범위

### 포함

- 원작 시스템 재현: 턴제 전투(반격 없음), 병과·상성, 책략(지형·날씨 게이트), 사기·혼란, 경험치·승급, 아이템, 일기토, 이벤트·분기·엔딩.
- 전 시나리오 콘텐츠 데이터 입력(사실·가상 양 루트)과 원작 동일 맵 재현.
- 편의 개선 2종: 전투 중 턴 중간 세이브/로드, 장수 정보 에디터.
- 커스터마이징 파이프라인(스프라이트 계약, 플레이스홀더 폴백, MODDING.md)과 맵 트레이싱 도구.
- 윈도우·맥 데스크톱 패키징(Tauri)과 GitHub Actions 릴리스 빌드 자동화.

### 제외

- 원작 파일 추출·원작 에셋 사용(하이브리드 리메이크 방침 — [ADR-001](./work/20260817-ygj-remake-baseline/ADR-001-하이브리드-리메이크와-데이터-주도-엔진.md)).
- 배포·공개(개인 사용 전용), 온라인·멀티플레이, 모바일 지원.
- 콘솔판 확장 요소: 풍계 책략, 에필로그 세부 분기(데이터 구조만 카테고리 추가로 확장 가능하게 유지).
- 자유 일기토(임의 장수 간 무력 판정) — `judge` 모드로 기반만 마련.

| NFR-01 | 결정론 | 전투 로직은 시드 기반 RNG만 사용하고 동일 입력→동일 결과를 보장해야 한다. 테스트는 restore 모드+고정 시드로 수행한다. |
| NFR-02 | 로직·렌더 분리 | `core/`는 PixiJS 등 렌더 의존 없이 단독 실행·테스트 가능한 순수 TypeScript여야 한다. |

| NFR-04 | 성능 | 적 페이즈 AI 계산은 100ms 이내여야 한다. 논리 해상도 1280×720, 정수 배율 스케일링을 지원해야 한다. |

| NFR-06 | 튜닝 가능성 | 전투·AI 상수는 전부 config JSON(`combat-config.json` 등)에 외부화하여 코드 수정 없이 조정 가능해야 한다. |
| NFR-07 | 저작권 준수 | 원작 추출물을 사용·포함해서는 안 된다. `reference/` 자료는 git에서 제외하고, 개인 사용·비배포 전제를 유지한다. |
| NFR-08 | 플랫폼 호환 | 윈도우·맥에서 실행 가능해야 하며, 맥 WKWebView의 오디오 정책·키 입력을 실기 검증해야 한다. |

## 인수 조건

| ID | 항목 | 내용 |
|---|---|---|
| AC-01 | 데이터 검증 | 존재하지 않는 ID 참조 또는 스프라이트 매핑 누락을 데이터에 넣고 `npm run validate`를 실행하면 해당 항목이 에러 목록으로 출력되고 실패 코드로 종료된다. |
| AC-02 | 전투 완주 | 테스트 스테이지 1개에서 배치→이동/공격→턴 교대→승패 판정까지 브라우저에서 전투 한 판을 완주할 수 있다. |
| AC-03 | 전투 규칙 재현 | 원작 1장 수준 전투에서 책략(지형·날씨 게이트 포함)·아이템·사기/혼란·경험치/레벨업/승급·일기토·전투 이벤트가 규칙 누락 없이 동작한다. |
| AC-04 | 상성 검증 | 상성 3×3 조합의 방어 보정 배수(±25%)와 지형·아이템 보정에 대한 단위 테스트가 통과한다. |
| AC-05 | 턴 중간 세이브 | 전투 중 플레이어 턴 임의 시점에 저장하고 앱을 종료·재시작 후 로드하면 턴·페이즈·유닛 상태·발동 이벤트·날씨·RNG 상태가 저장 시점과 일치한 채 재개된다. |
| AC-06 | 세이브 라운드트립 | 임의 BattleState의 직렬화→역직렬화 왕복이 상태 완전 일치하고, restore 모드에서 로드 후 동일 커맨드 열이 동일 결과를 낳는다(랜덤 커맨드 시퀀스 100회 속성 기반 테스트). |
| AC-07 | 맵 도구 | 맵 트레이싱 도구에서 원작 스크린샷을 반투명 오버레이로 정렬하고 원작 맵 1개를 타일 단위로 재현하여 stages JSON으로 내보낼 수 있다. |
| AC-08 | 전 시나리오 플레이 | 처음부터 사실·가상 양 루트 엔딩까지 연속 플레이할 수 있고, 전 스테이지가 `unverified` 0으로 검수 체크리스트를 통과한다. |
| AC-09 | 장수 에디터 | 범위 밖 값(능력치 0·101, 레벨 0·100)이 입력 단계에서 차단되고, 수정값이 세이브·전체 UI·새 캠페인 합류(joinLevel)에 반영되며, 오버레이 삭제로 원작 값이 복원된다. 오버레이는 `dataHash` 경고를 유발하지 않는다. |
| AC-10 | 병종 추가 개조 | MODDING.md 절차만으로 새 병종을 추가하면 엔진 코드 수정 없이 validate가 통과하고 맵 유닛·상태창·편성·전투 로그 UI에 자동 반영된다. |
| AC-11 | 패키징·빌드 | `v*` 태그 푸시 1회로 GitHub Release에 윈도우 설치본과 맥 .dmg가 자동 생성되고, 각 OS 실기에서 더블클릭 실행이 확인된다. |
| AC-12 | AI 성능 | 적 20부대 규모 스테이지에서 적 페이즈 전체 AI 계산이 100ms 이내에 완료된다. |

## 제약과 의존성

- 기술 스택 확정: TypeScript(strict)·Vite·PixiJS v8·DOM 오버레이 UI·Zustand·zod·Vitest·Tauri v2·Howler.js — [ADR-002](./work/20260817-ygj-remake-baseline/ADR-002-기술-스택-선정.md).
- 데이터 출처: 커뮤니티 위키·공략 자료·플레이 영상. 원작 파일은 사용하지 않는다(NFR-07).
- **문서 우선순위**: 선행 명세 간 충돌 시 상세 스펙 > 전체 설계(상세 스펙 머리말 선언). 본 기준선과 선행 명세가 충돌하면 이 워크플로우(wf-design)의 DCR·재승인 절차로 해소한다.
- GitHub 프라이빗 리포지토리와 GitHub Actions 무료 분수(개인 계정) 사용을 전제한다.
- 마일스톤 분해(M0~M6)는 [전체 설계 §8](../yeonggeoljeon-remake-design.md)을 계획 입력으로 사용하되, 작업 분해·순서는 wf-implement 계획이 소유한다.

## 가정과 미해결 질문

가정:

- 선행 명세의 `[검증]` 표기 수치는 커뮤니티 추정 초기값으로 구현하고 M2·M4에서 원작 실측 대조로 보정한다. 상수는 config JSON에 외부화되므로 코드 변경 없이 조정 가능하다(낮은 위험 — 명시 후 진행).
- 개발 머신(윈도우)에 Node.js LTS·npm을 설치·사용할 수 있다. M0 시작 조건에서 확인한다.
- 원작 대조 자료(DOSBox 스크린샷·플레이 영상·공략)는 사용자가 확보 가능하다(상세 스펙 §6.4 전제).
