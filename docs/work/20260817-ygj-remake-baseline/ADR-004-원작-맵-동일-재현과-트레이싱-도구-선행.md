# ADR-004: 원작 맵 동일 재현과 트레이싱 도구 선행

## 요약

- 결정: 인게임 맵의 논리 구조(크기·지형·배치·보물·증원 좌표)는 간략화 없이 원작과 동일하게 재현하고, 이를 위해 맵 트레이싱 도구(M3.5)를 먼저 만들며 도구 완성 전에는 맵 입력을 시작하지 않는다.
- 핵심 이유: 간략화는 원작 디테일(요충지·보물 위치·증원 경로)을 잃기 쉽고, 도구 없는 수작업 트레이싱은 낭비가 크다.
- 주요 단점: 맵 재현이 최대 물량 작업이 되고, 도구 개발이 콘텐츠 입력(M4)의 선행 조건이 된다.

## 배경

맵 재현 수준으로 간략화 재현과 동일 재현이 경쟁한다. 원작 영걸전의 전투 디테일(지형 요충지, 보물고 위치, 증원 경로)은 맵 좌표에 결합되어 있어 간략화 시 유실된다. 한편 타일 단위 트레이싱은 50개 내외 스테이지에 대한 최대 물량 작업이다.

## 영향을 받는 요구사항과 제약

- [FR-14](../../requirements.md) 원작 맵 동일 재현, [FR-15](../../requirements.md) 맵 트레이싱 도구, [AC-07·AC-08](../../requirements.md).
- 제약: 원작 대조 자료는 DOSBox 캡처·플레이 영상·공략 자료(개인 참고용, `reference/` git 제외).

## 고려한 대안

| 대안 | 장점 | 단점·위험 | 전환 비용 |
|---|---|---|---|
| 간략화 재현(느낌만 유사한 맵) | 물량 대폭 감소 | 원작 디테일 유실 — 요충지·보물·증원 경로가 무의미해짐, 사용자 방침과 상충 | 낮음(부적합) |
| 동일 재현, 도구 없이 수작업 JSON 입력 | 도구 개발 생략 | 맵 1개당 작업 시간 과다, 오류 검수 곤란, 중도 포기 위험 증가 | 중간 |
| 동일 재현+트레이싱 도구 선행 (선택) | 맵당 작업 시간 최소화, 대조 토글로 검수 내장, `unverified` 추적 | M3.5 도구 개발 비용, M4가 도구에 의존 | — |

## 결정

- 맵 논리 구조는 원작과 동일하게 입력한다(간략화 금지). 시각 표현만 교체 허용.
- M3.5에서 인브라우저 트레이싱 도구(참조 이미지 오버레이·팔레트 페인팅·유닛/오브젝트 배치·대조 토글·stages JSON 직접 입출력)를 먼저 완성한다.
- **도구 완성 전에는 맵 입력을 시작하지 않는다**(수작업 낭비 방지).
- 근거 미확보 타일은 `unverified` 마킹하고, M4 완료 기준은 전 스테이지 `unverified` 0+검수 체크리스트 통과다.

## 이유

- 원작 플레이 감각의 상당 부분이 맵 좌표에 결합되어 있어 동일 재현이 목표(원작 감각 유지)에 직결된다.
- 도구 선행이 스테이지당 한계 비용을 낮춰 총 물량 위험(RISK-02·03)을 가장 효과적으로 줄인다.

## 결과와 감수할 단점

- M4(콘텐츠 입력)는 M3.5 완료에 의존한다. 로드맵상 병행 가능 범위는 wf-implement 계획이 정한다.
- 스테이지별 검수 체크리스트([상세 스펙 §6.3](../../../yeonggeoljeon-remake-spec-detail.md)) 운용 비용을 감수한다.

## 후속 작업

- M3.5 도구 구현과 원작 맵 1개 파일럿 재현(AC-07, wf-implement 소유).
