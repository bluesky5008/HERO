# ADR-005: 장수 에디터 오버레이 전역 적용

> 문서 유형: `adr`
> 작업 ID: `20260817-ygj-remake-baseline`
> 상태: `approved`
> 기준선: `N/A — 기준선은 요구사항·설계 문서가 보유`
> 작성일: 2026-08-17
> 최종 갱신: 2026-08-17
> 관련 문서: [REQ-ygj-remake: 요구사항 명세](../../requirements.md), [DESIGN-ygj-remake: SW 설계](../../design.md)

## 요약

- 결정: 장수 에디터의 편집 결과는 기본 데이터를 수정하지 않고 사용자 오버레이 파일(`officers-user.json`·`portraits-user.json`)에 기록하며, 로더가 필드 단위로 병합해 전역 적용(진행 중+새 캠페인)한다. 오버레이는 세이브 `dataHash` 계산에서 제외한다.
- 핵심 이유: 원본 불변으로 언제든 복원 가능하고, 공식 기능 사용이 세이브 호환성 경고를 유발하지 않는다.
- 주요 단점: 병합·폴백 로직과 레벨의 2갈래 적용(현재 캠페인 즉시+`joinLevel`) 복잡성을 감수한다.

## 배경

게임 내 장수 편집(능력치·레벨·초상화)의 적용 범위와 저장 방식이 필요하다. 후보: 기본 데이터 직접 수정, 캠페인(세이브) 단위 적용, 사용자 오버레이 전역 적용. 선행 명세 v1.1이 오버레이 전역 적용을 확정했고 본 ADR은 그 근거를 기록한다.

## 영향을 받는 요구사항과 제약

- [FR-16](../../requirements.md) 장수 정보 에디터, [AC-09](../../requirements.md), [NFR-05](../../requirements.md)(dataHash 규칙과의 상호작용).
- 제약: 능력치 1~100·레벨 1~99는 스키마 제한을 그대로 강제. 편집 대상은 능력치·레벨·초상화 3종으로 한정.

## 고려한 대안

| 대안 | 장점 | 단점·위험 | 전환 비용 |
|---|---|---|---|
| 기본 `officers.json` 직접 수정 | 병합 로직 불필요 | 원작 값 복원 곤란, dataHash 변경으로 세이브 경고 유발, 모딩과 공식 기능의 경계 소실 | 낮음(부적합) |
| 캠페인(세이브) 단위 적용 | 캠페인별 독립 실험 가능 | "새 캠페인에도 반영" 요구 미충족, 세이브마다 중복 편집 필요 | 중간 |
| 사용자 오버레이 전역 적용 (선택) | 원본 불변·삭제만으로 복원, 전 캠페인 일괄 반영, dataHash 비간섭 | 병합·폴백 로직, 레벨 2갈래 적용 복잡성 | — |

## 결정

- 편집 결과는 `officers-user.json`(능력치·`joinLevel`)·`portraits-user.json`(초상 매핑)에 기록하고 로더가 기본 데이터 위에 필드 단위 병합한다(오버레이 우선).
- 적용 의미: 능력치·초상화는 전 캠페인·세이브에 즉시 반영. 레벨은 ① 현재 캠페인 즉시 변경(경험치 유지, 파생치 재계산) ② `joinLevel` 갱신(새 캠페인 합류 시작 레벨). 다른 기존 세이브의 레벨은 소급하지 않는다.
- 오버레이는 `dataHash` 계산에서 제외하고, 로드 시 별도 참조 무결성 검사+기본값 폴백을 적용한다.
- 저장 위치: 사용자 데이터 영역(개발 IndexedDB / 패키징 `appDataDir()/user-data`), `AssetStore` 패턴으로 추상화. "전체 초기화" 버튼 제공.

## 이유

- 원본 불변이 복원 가능성(요구사항)과 개조(모딩)·공식 기능의 명확한 분리를 동시에 보장한다.
- dataHash 제외로 에디터 사용이 세이브 호환성 경고를 오염시키지 않는다 — 개조 감지 기능의 신호 품질 유지.

## 결과와 감수할 단점

- 데이터 로더에 병합 단계가 추가된다(DES-03). 오버레이 참조 무결성 검사와 폴백 경로를 별도 테스트해야 한다.
- 레벨 편집 규칙(경험치 유지, 승급 유지, 상한 재계산)은 [상세 스펙 §11.3](../../../yeonggeoljeon-remake-spec-detail.md)을 정본으로 구현한다.
