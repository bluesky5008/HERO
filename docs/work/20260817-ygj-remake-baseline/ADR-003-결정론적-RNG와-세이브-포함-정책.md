# ADR-003: 결정론적 RNG와 세이브 포함 정책

## 요약

- 결정: 전역 RNG는 직렬화 가능한 xoshiro128**로 구현하고, 전투 중 세이브에 RNG 상태를 포함하며, 로드 시 동작은 설정 `rngOnLoad: reseed(기본) | restore`로 사용자가 선택한다.
- 핵심 이유: 결정론(테스트·리플레이·튜닝)과 조조전식 세이브/로드 리세마라 플레이 감각을 옵션으로 양립시킨다.
- 주요 단점: 모든 난수 소비 경로가 전역 RNG를 경유해야 하는 구현 규율이 필요하다.

## 배경

전투 중 임의 시점 세이브(FR-12)는 로드 후 상태가 저장 시점과 완전히 일치해야 한다. 난수 상태가 세이브에 없으면 "로드→같은 행동→같은 결과"를 보장할 수 없고, 테스트 재현성도 무너진다. 한편 조조전식 플레이 감각(로드 후 재추첨으로 결과 되굴리기)을 원하는 취향도 존재한다.

## 고려한 대안

| 대안 | 장점 | 단점·위험 | 전환 비용 |
|---|---|---|---|
| `Math.random()` 사용 | 구현 최소 | 비결정론 — 테스트 재현·상태 복원 불가, NFR-01 위반 | 낮음(부적합) |
| 시드 RNG, 세이브에 상태 미포함 | 구현 단순 | 로드 후 난수열 재현 불가, AC-05·AC-06 충족 불가 | 낮음(부적합) |
| 직렬화 가능 시드 RNG+상태 저장+로드 정책 옵션 (선택) | 결정론과 리세마라 감각 양립, 속성 기반 테스트 가능 | 전 난수 경로의 전역 RNG 경유 규율 필요 | — |

## 결정

- 알고리즘: xoshiro128**(128bit 상태, 구현 간단, 직렬화 용이). 전투 시작 시드 = 캠페인 시드+스테이지 ID+진입 횟수.
- 세이브 포맷에 `rng: { algo, state }`를 포함한다.
- 로드 동작: `reseed`(기본 — 로드 시 재추첨, 조조전식) / `restore`(상태 복원 — 같은 행동→같은 결과). 테스트는 항상 restore+고정 시드.

## 이유

- 상태를 저장해야만 두 정책 모두 구현 가능하다(restore는 필수, reseed는 선택적으로 버림).
- 결정론 코어는 속성 기반 테스트(랜덤 커맨드 100회 시퀀스)와 실측 튜닝 비교의 전제다.

## 결과와 감수할 단점

- `core/` 안에서 `Math.random()` 사용을 금지하고 모든 난수를 `Rng` 인터페이스로 주입한다(코드 리뷰 관점).
- 세이브 포맷에 RNG 필드가 고정된다 — 알고리즘 교체 시 `version` 마이그레이션 필요.
